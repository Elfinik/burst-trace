# Продвинутое использование
## Временное отключение логирования через скрипт
Вы можете временно отключить создание логов. Это не вырежет код из сборки, но исключит выполнение кода создания логов, сведя влияние их вызова практически на ноль. Для этого вызовите
```CSharp
BurstTrace.SetLogDisabled(true);
```
Укажите `true` для выключения логов, укажите `false` для включения логов.
Вы можете узнать включены ли логи используя функцию
```CSharp
BurstTrace.IsLogEnabled();
```
Если логи выключены ИЛИ вы исключили код плагина из релизной сборки, функция вернет `false`. Если логи включены, вернет `true`
## Отключение в релизе
Вы можете полностью исключить код из релизной сборки, поставив галочку в `ProjectSettings > BurstTrace > Disable logs`

Это исключит код создания логов, но не сделает структуру `TraceHandle` пустой. Она всё так же будет занимать 4 байта, но её значение всегда будет пустым. Это сделано, чтобы избежать теоретических проблем с сериализацией и структурой памяти между запусками.

Сам код создания превратится в пустые методы, поэтому его вызов внутри Burst не будет ничего стоить, так как Burst должен будет его просто вырезать. Вызов вне Burst также крайне дешевый, так как это просто вызов пустого метода.
## Автоматическое создание логов без написания кода в месте вызова
Если вы хотите сделать функцию, которая автоматически создаст лог вызывающей строки, вместо того, чтобы вручную вызывать и передавать `TraceHandle`, используйте следующий шаблон:
```CSharp
    public void WriteDamageEvent(DamageEvent damageEvent, [CallerMemberName] string memberName = "", [CallerFilePath] string sourceFilePath = "", [CallerLineNumber] int sourceLineNumber = 0)
    {
        this.damageSenderTraceHandle = BurstTraceAdvanced.RegisterLog(damageEvent.burstTrace, memberName, sourceFilePath, sourceLineNumber);
    }
```
В этом примере функции передается `DamageEvent`, но также вы можете ничего не передавать. Главное здесь: 3 аргумента
```CSharp
[CallerMemberName] string memberName = "",
[CallerFilePath] string sourceFilePath = "",
[CallerLineNumber] int sourceLineNumber = 0
```
Добавьте их в функцию, а потом передайте в вызов регистрации кастомного лога:
```CSharp
        TraceHandle customTraceHandle = BurstTraceAdvanced.RegisterLog(memberName, sourceFilePath, sourceLineNumber);
```
Вы также можете передать первым аргументом другой `TraceHandle`, чтобы создать цепочку.
Дальше просто вызывайте свою функцию как обычно:
```CSharp
        WriteDamageEvent(damageEvent);
```
**НЕ ПРИСВАИВАЙТЕ ДАННЫЕ ЭТИМ СЛУЖЕБНЫМ АРГУМЕНТАМ ПРИ ВЫЗОВЕ ФУНКЦИИ! Не передавайте значения в эти аргументы вручную, компилятор заполнит их автоматически.**
Таким образом вы можете, например, создать функцию, которая при вызове будет записывать место, из которого она была вызвана, при этом не требуя написания дополнительного кода во время её вызова.
Вы также можете использовать это внутри Burst, внутри параллельных Jobs.
> Обратите внимание: этот метод немного медленнее стандартного `TraceHandle.Capture()`. Используйте его только если вам важно скрыть вызов логирования внутри метода. В производительности он уступает совсем **чуть-чуть**.
## Вывод логов для дальнейшего изучения
Если вам нужно получить полную строку лога, вызовите
```CSharp
traceHandle.ToAbsolutePath();
```
Это вернет построчный вывод цепочки логов.
Если вы вызываете
```CSharp
traceHandle.ToProjectLink();
```
Вы получаете следующий формат (зависит от версии Unity):
```CSharp
#if UNITY_6000_0_OR_NEWER
string link = $"<color=#40a0ff><link=\"href='{relativePath}' line='{lineNum}'\">{relativePath}:{lineNum}</link></color>";
#else
string link = $"<a href=\"{relativePath}\" line=\"{lineNum}\">{relativePath}:{lineNum}</a>";
#endif
```
>[!NOTE]
> Обратите внимание: вызов этой функции внутри билда будет практически идентичен вызову `ToAbsolutePath`. Гиперссылки не будут добавлены, так как в сборке отсутствуют файлы скриптов. Вы будете видеть корректный вывод файлов и строк, но с абсолютными путями и без возможности клика.
## Настройка ProjectSettings
Вы можете настраивать аспекты плагина в меню  `ProjectSettings > BurstTrace`

⚠️ Не меняйте имя и путь к файлу! Он должен иметь путь `Resources/Burst Trace Config.asset`

### Memory optimization mode (~x3)
> Включение этой опции оптимизирует использование памяти хранилища примерно в 3 раза. Взамен она создает незначительные накладные расходы во время первоначальной регистрации логов и при их чтении, а также может нарушить работу логирования (повредить вывод строки) для проектов с глубокой внутренней вложенностью (внутри `Assets`). Не рекомендуется включать эту опцию, если локальный путь (внутри `Assets`) к вашим скриптам превышает 124 байта!

### Disable 64-hash optimization
> Плагин заменяет строки на хэши для оптимизации. По умолчанию используется 64-битный хэш. Шанс коллизии ничтожно мал, но теоретически существует.
> Если вы столкнетесь с хэш-коллизиями (пожалуйста, создайте Issue в репозитории), включите эту опцию. Она немного снизит производительность, увеличит использование памяти, но полностью исключит вероятность коллизий.

### Capture profiler
>Включите эту галочку, чтобы момент создания и записи логов отображался в Unity Profiler. Он также будет показываться внутри Jobs. Так вы сможете точно узнать стоимость использования внутри ваших Jobs. В релизе рекомендуется выключить это, так как запись в Profiler теоретически может быть дороже, чем само создание лога.

### Disable logs
>Это исключит код создания логов из сборки, но не сделает структуру `TraceHandle` пустой. Она всё так же будет занимать 4 байта, но её значение всегда будет пустым. Это сделано, чтобы избежать теоретических проблем с сериализацией и структурой памяти между запусками.
  Сам код создания превратится в пустые методы, поэтому его вызов внутри Burst не будет ничего стоить, так как Burst должен будет его просто вырезать. Вызов вне Burst также крайне дешевый, так как это просто вызов пустого метода.
